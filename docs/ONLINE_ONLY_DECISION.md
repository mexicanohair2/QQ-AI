# Решение: сначала только онлайн QQ AI

Дата: 2026-11-21

Этот документ обновляет прежний гибридный план. На текущем этапе QQ AI разрабатывается только как онлайн-приложение. Локальную загрузку и запуск весов в браузере, офлайн-режим, ONNX/WebGPU и локальный Qwen пока не реализуем.

## Загрузка модели

Веса должны находиться на инфраструктуре провайдера/сервере инференса. Браузер загружает только интерфейс и отправляет сообщения на защищённый серверный маршрут `/api/chat`. Пользователь не должен выбирать файл модели, скачивать сотни мегабайт или ждать загрузки весов на телефон.

Для первой интеграции выбран Qwen через OpenAI-совместимый API DashScope. Серверные переменные:
- `QWEN_API_KEY` — обязательный секрет;
- `QWEN_BASE_URL` — необязательный адрес API;
- `QWEN_MODEL` — необязательное имя модели.

Ключ нельзя помещать в клиентский JavaScript или репозиторий. До настройки ключа сайт должен показывать ясное сообщение о том, что сервер ещё не подключён, а не бесконечный индикатор загрузки.

## Эталон UX

Kimi используется только как функциональный ориентир, не как копируемый дизайн. Важно перенять принципы: один очевидный чатовый поток, история разговоров, переключение режимов/моделей в понятном месте, вложения, потоковая выдача, остановка генерации, поиск с источниками и память с контролем пользователя. Визуальный язык QQ AI остаётся самостоятельным: спокойный бордово-фиолетовый, без резкого неона.

## Обучение

Подготовка авторского датасета начинается отдельно от пользовательских чатов. Запрещено автоматически использовать приватные переписки как обучающие данные. Небольшой seed-набор — только проверка формата, не обучение. Реальное обучение/LoRA начинается после выбора базовых весов, подготовки большого лицензированного корпуса, GPU-среды и тестового набора.

## Границы текущей работы

- Не изменять QQCross.
- Не добавлять офлайн-режим.
- Не называть Qwen собственной моделью QQ AI.
- Не утверждать, что обучение состоялось, пока не запущен train-job и не сохранён проверяемый артефакт.
- GitHub Pages не исполняет API-функции; приложение с серверным маршрутом нужно разворачивать на платформе с serverless functions, например Vercel.
