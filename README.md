# QQ AI

QQ AI — независимый русскоязычный ИИ-помощник. Сейчас развивается как веб-приложение; в будущем его интеллект планируется встроить в QQCross.

**Сейчас не разрабатываем APK.** Не добавлять Android-оболочку, Capacitor или APK-сборку в текущие этапы. Сначала доводим веб-QQ AI и его ИИ. Позже отдельно интегрируем проверенный игровой модуль в QQCross; APK будет относиться к объединённой игре, если пользователь отдельно утвердит этот этап.

## Цели QQ AI

- Сильный онлайн-помощник с проверкой фактов и многошаговым рассуждением.
- Локальный Qwen как резервный текстовый режим без интернета.
- Интернет-поиск с настоящими источниками и ссылками.
- Голосовой ввод с редактированием расшифровки до отправки.
- Прикрепление изображений и анализ текста, чисел, формул, таблиц, графиков и содержимого снимков.
- Прикрепление видео с анализом ограниченного числа кадров и временными метками; анализ аудио — отдельная функция.
- QQ Knowledge — личная расширяемая база знаний с источниками и поиском по содержимому.
- Аккаунты, история, настройки и синхронизация через Supabase.
- Отдельный игровой интеллект QQ Game AI для будущего подключения к QQCross.

Эти пункты — целевой объём, а не заявление, что все функции уже работают. Реальный статус каждой возможности должен быть отражён в интерфейсе и проверен тестами.

## Текущая реализация и ограничения

### Чат и модели
- **Онлайн:** основной режим интерфейса. `/api/chat` использует QQ AI Model Gateway с OpenAI-compatible Chat Completions API. Поддерживаются официальный OpenAI API и DeepSeek API: `QQ_AI_API_URL`, `QQ_AI_MODEL`, общий серверный ключ `QQ_AI_API_KEY` или алиасы `OPENAIAPIKEY` / `DEEPSEEK_API_KEY`. Для DeepSeek используются `https://api.deepseek.com/chat/completions` и актуальное имя модели `deepseek-flash`; шлюз задаёт `max_tokens` и низкую интенсивность рассуждения. Ключи никогда не передаются в браузер. Для GPT-6 reasoning-моделей сохраняется поддерживаемый OpenAI формат `max_completion_tokens`.
- **Офлайн:** Qwen2.5-0.5B запускается через WebLLM и WebGPU; модель кэшируется в IndexedDB.
- Офлайн-модель небольшая и уступает современным облачным моделям в сложных задачах.
- Пока серверная модель QQ AI не размещена: без `QQ_AI_API_URL` и `QQ_AI_MODEL` API честно возвращает `ONLINE_MODEL_UNCONFIGURED`. Онлайн-режим больше не переключается молча на Qwen.
- Если выбранный inference-сервер требует секрет, он хранится только в защищённых серверных переменных. Не отправлять ключи в чат и не добавлять в исходники.
- Наличие `OPENAIAPIKEY` или `DEEPSEEK_API_KEY` в Vercel не означает, что API включён: для Online отдельно нужны `QQ_AI_API_URL` и `QQ_AI_MODEL`, а ключ должен быть доступен нужной среде Vercel (Preview/Production). DeepSeek API тарифицируется по токенам; создание ключа само по себе не означает бесплатный баланс. Не активировать и не тестировать платные запросы без явного согласия взрослого владельца проекта.
- Не включать платное пополнение или расходование средств без отдельного согласия взрослого владельца проекта.

### Голос
- Есть два варианта голосового ввода: браузерный SpeechRecognition и локальная Whisper Tiny через отдельный Transformers.js/WebGPU Worker.
- Для локального пути пользователь отдельно загружает мультиязычную модель (примерно 70–90 МБ с учётом служебных файлов), разрешает микрофон и записывает фразу до 20 секунд. Запись обрабатывается на устройстве; аудио не отправляется на сервер и не сохраняется в истории.
- Локальный звук приводится к mono/16 кГц, передаётся Worker в памяти и удаляется после распознавания. Текст вставляется в поле сообщения и остаётся редактируемым — автоматической отправки нет.
- Локальный режим требует WebGPU, MediaRecorder и AudioContext. Точность Whisper Tiny может быть ограниченной; распознанный текст нужно проверить. На Honor 400 физический тест пока не проводился.
- Чтобы снизить риск нехватки видеопамяти на телефоне, QQ AI держит активной только одну тяжёлую локальную модель (текст, Vision или Whisper). При переключении предыдущая GPU-сессия выгружается, но веса остаются в кэше браузера.
- Браузерный SpeechRecognition остаётся запасным вариантом, но в зависимости от браузера может отправлять аудио удалённому сервису; его нельзя называть локальным.

### Изображения, видео и поиск
- Добавлены `/api/search` и поиск по намерению внутри `/api/chat`. Отдельная кнопка QQ Search запускает поиск напрямую и работает независимо от генеративной модели. DuckDuckGo, Bing и открытый API русской Википедии запрашиваются параллельно; Википедия служит независимым бесплатным резервным источником, если HTML-поисковики не отвечают или меняют разметку. Результаты дедуплицируются, ссылки нормализуются до HTTPS, заголовки и фрагменты экранируются перед выводом. В выдаче показываются поисковые фрагменты без выдачи их за AI-пересказ. Полное извлечение страниц и перекрёстная проверка источников ещё не готовы.
- Добавлен интерфейс прикрепления фото/видео, локальное сжатие изображений и выбор кадров с временными метками. В локальном режиме отдельный WebGPU Worker запускает SmolVLM-256M через Transformers.js; фото и кадры видео остаются в браузере, для видео выбираются до четырёх кадров, аудио не анализируется. Загрузка модели (~190–270 МБ по файлам весов, плюс служебные файлы) начинается только после явного нажатия пользователя.
- Локальная Vision-модель небольшая и англоязычная: качество русского текста, OCR, мелких деталей, таблиц и формул ограничено и пока не оценено. Требуется WebGPU и достаточно памяти; запуск на Honor 400 ещё не проверен.
- `/api/vision` остаётся отдельным облачным маршрутом. Для него необходимы серверные `QQ_AI_VISION_API_URL` и `QQ_AI_VISION_MODEL`; сейчас облачная Vision-модель не размещена. В режиме Online облачный путь используется только если он реально настроен, иначе доступен явно загруженный локальный Vision.
- Перед выбором vision/search-провайдера проверить API, бесплатные лимиты, необходимость карты, возрастные условия, регион, приватность и хранение данных.
- До размещения собственной онлайн-модели текстовая генерация онлайн недоступна. `/api/chat` возвращает `ONLINE_MODEL_UNCONFIGURED`; поиск работает отдельно как выдача ссылок и фрагментов.
- После развёртывания модели сравнить её на одной и той же русскоязычной матрице с Qwen2.5-0.5B; не заявлять превосходство до результатов benchmark.

### QQ Game AI
- Типы игровых задач и проверка ответов находятся в `src/lib/qqcross-ai.ts`.
- Клиентский адаптер находится в `src/lib/qqcross-ai-client.ts`.
- Серверный маршрут `POST /api/game-assistant` проверяет Supabase-сессию и использует ту же QQ Online модель через `QQ_AI_API_URL` и `QQ_AI_MODEL`.
- Поддерживаемые задачи контракта: подсказка без раскрытия ответа, объяснение связи вопроса и ответа, черновики вопросов только для заранее утверждённого списка ответов.
- Ответы модели проходят структурную проверку. Игровой ИИ не меняет сетку, словарь, ответы, координаты, пересечения или состояние матча.
- Этот маршрут ещё не подключён к клиенту QQCross. Реальная доступность зависит от серверных переменных и успешного теста авторизованного запроса.
- QQCross не менять до отдельного явного этапа интеграции.

### Общие контракты
- `src/lib/ai-contracts.ts` задаёт provider-neutral типы для текста, поиска, изображений, видеокадров и игровых задач.
- Наличие интерфейса/типа не означает, что соответствующий провайдер подключён или функция готова.

## Supabase

- Supabase Auth — вход по электронной почте.
- Supabase хранит историю диалогов, настройки и пользовательские данные.
- Таблицы пользовательских данных должны иметь RLS и проверку изоляции между аккаунтами.
- Память выключена по умолчанию; записи нормализуются, считаются недоверенными данными, сохраняются локально по отдельным ключам аккаунтов и синхронизируются с облаком по времени последнего изменения.
- Не хранить исходные медиафайлы по умолчанию. Не отправлять содержимое в облако без явного действия и понятного уведомления.

## Безопасность и расходы

- Секреты — только на сервере.
- Не просить пользователя присылать API-ключи, пароли или токены.
- Не подключать платный API, подписку, автоматическое пополнение или карту без явного согласия.
- Соблюдать возрастные условия провайдеров; не обходить проверки возраста.
- Не логировать ключи, токены, сырые медиа и полную приватную переписку.
- Любой текст из интернета, файлов, OCR и базы знаний считать недоверенными данными, а не инструкциями для модели.

## QQ AI model development

- [QQ AI model ownership and training roadmap](docs/QQ_AI_MODEL_TRAINING_ROADMAP.md) describes the route toward a QQ-maintained fine-tuned checkpoint and self-hosted inference, without claiming that a foundation model has already been trained.
- [Russian benchmark dataset](evals/qq-ai-benchmark.ru.json) contains reasoning, math, web, vision, video, safety, and knowledge tasks with evaluation rubrics.
- Run a text-only benchmark against a configured OpenAI-compatible QQ inference endpoint with `QQ_AI_API_URL`, `QQ_AI_MODEL`, and optionally `QQ_AI_API_KEY`:
  `node scripts/run-qq-ai-benchmark.mjs`
- Media-only benchmark cases are intentionally excluded by the runner until a real vision/video model endpoint is configured. The benchmark runner records outputs and latency; it does not assign quality scores automatically.
